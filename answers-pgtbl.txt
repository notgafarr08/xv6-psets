Each page table entry shows a virtual address (VA), its physical address (PA), and permission bits. `0x5B` means valid, readable, executable, user-accessible, and accessed — used for user code/text. `0x17` means valid, readable, writable, user-accessible — for user data/heap. `0x7` means valid, readable, writable but kernel-only — for kernel mappings. `0xD7` means valid, readable, writable, user-accessible, accessed, dirty — for writable user pages like stack or heap. Entries with `0x0` are unmapped (invalid) and cause page faults if accessed. `0xC7` means valid, readable, writable, accessed, dirty but kernel-only — used for trapframe or kernel stack. `0x4B` means valid, readable, executable, accessed, kernel-only — used for the trampoline page at the top of memory. Unmapped addresses like `0x3FFFFFD000` lead to traps (`scause 0xd`) when accessed. Overall, low addresses (`0x0–0x4000`) map user code/data, while high addresses map kernel structures like the trapframe and trampoline.
